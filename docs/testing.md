# Test and security regression matrix

Public test sources are grouped in `dev/测试/`: `单元/`, `CLI/`, `桌面/`, `smoke/`, and `fixtures/`. The ignored root `测试/运行产物/` remains the data location so historical evidence is not relocated or rewritten. Historical reports retain their original source paths and hashes; they certify only their named candidates. The `0.2.1` report records the current source, build, artifact and host evidence.

The test suite is intentionally split into deterministic unit/contract tests and conditional Windows/WSL integration tests. A skipped integration test must state the missing capability (for example `Git Bash executable not found` or `bwrap unavailable`) and is not a pass.

## Required coverage

| Area | Regression assertion |
| --- | --- |
| Configuration | Plugin `0.2.1` with exact Desktop or CLI DSH `0.2.1-rc.2`, Node `>=22`, Ubuntu and clean Bash defaults; malformed configuration fails before execution. |
| Actual host identity | Read `profileContext.installAnchor`, reject missing/relative/invalid anchors and unsupported versions even when a supported peer package exists nearby. |
| System instructions | Exactly one official prompt section, ordered after `TOOL_BASH`, interpolation disabled, no personal data; unload removes it and reload does not duplicate it. |
| Git Bash discovery | Deterministic configured/path/default priority; reject UNC, device namespace, directories, and non-executable candidates. |
| Path handling | Windows↔WSL conversion round-trips spaces and Chinese names; production uses the selected distribution's actual `wslpath` plus `realpath`, passes the validated Windows path to `wsl.exe --cd`, supports a non-`/mnt` automount root, and rejects `..`, symlink/junction escapes, drive roots, broad mount roots, UNC, and device paths. |
| Command boundary | `command` is a Bash program, so Bash syntax such as quotes, newlines, `$()`, backticks, semicolons, and globs executes as intended. Physical persistent input preserves TAB/ESC/DEL and other control bytes by escaping them before terminal transport and rejects NUL. The `command`, `workdir`, `description`, and related fields remain in their defined argv/parameter slots and cannot inject an outer PowerShell wrapper or extra `wsl.exe`/`bwrap` options. |
| Output and limits | One-shot stdout/stderr truncation is explicit and each captured stream is capped at 64 MiB (or a lower configured cap). WSL's `script` PTY merges program stderr into captured stdout: send a separate `>&2` payload and verify that merged stream's cap and permission-denial classification, rather than treating outer process stderr as program stderr. Structured spawn/runner/invalid-request failures are preserved and rendered. Check malformed UTF-8 using the actual rendered byte count, not only report metadata. Persistent scrollback, 256 KiB UTF-8-safe fallback and rendering use their separate bounds; any capture gap inside a command interval reports incomplete even with valid markers. |
| Persistent completion | Normal operation settlement before the deadline plus a real current-nonce numeric END frame completes even if background output has evicted it from latest scrollback. Preserve earlier incremental prefixes across operations; reject malformed, missing or foreign frames. Deadline/abort after a frame is observed still takes priority; no fabricated success or changed timeout. Validate through the mounted plugin adaptation and the actual host's public terminal/tool services. |
| WSL prompt production | The readonly prompt hook clears PS1 and emits the OSC marker plus complete controlled prompt text in one short `printf`; direct script environment and bwrap environment must agree. Every Bash launch clears startup-control variables and establishes trusted `SHELL=/bin/bash`; a `BASH_ENV` outside marker must remain absent. Repeat the finite background-output sequence on the actual hosts. Retain continuous bounded raw stdout for a failure; synthetic prefix/tail concatenation cannot establish byte order. Promptless, incomplete, mismatched and wrong-foreground readiness must still fail. |
| Deadline boundary | Expiry between polls, or a send rejected under the tool's actual `PERSISTENT_BASH_TIMEOUT`, returns the canonical timeout/reset result and reaps the owner shell. Preserve partial output and the configured deadline. Ordinary transport errors without that host deadline fact remain errors; no text-based timeout classification. |
| Timeout/cancel | Model-facing persistent `bash` timeout/cancellation resets and closes the owner shell; the next call creates a clean shell. Caller cancellation must start owner-scoped termination while `operation.done` is still pending, await cleanup before releasing the owner queue, and leave other owners untouched. Lower-level `startSend` signal/settlement tests are separate implementation-detail coverage. One-shot WSL/Git Bash timeout or cancellation kills the complete managed process tree and settles once. |
| Approval | Restricted Git Bash denial starts zero processes. Unavailable/rejected approval starts zero processes. Only the exact command/cwd/mode approved for a single retry can spawn. |
| Sandbox | A model `workdir` cannot change the writable root. Missing `bwrap`, `script`, WSL, or policy provider fails closed. Restricted WSL modes mask the `/run` Windows interop broker and unset `WSL_INTEROP`/`WSLENV`; `danger-full-access` intentionally retains interop. This targeted guard is not general IPC or network isolation. |
| Windows-outside marker | On a real Windows+WSL host, a restricted WSL command attempts to use `cmd.exe` to create a marker outside the immutable workspace; the marker must remain absent. Record a concrete missing Windows/WSL capability as a skip, not a pass; `danger-full-access` is not evidence for this restricted assertion. |
| Agent ownership | Agent A cannot list/read/send/signal/close Agent B's persistent session. Session mode/backend cannot be changed after creation. |
| Lifecycle | Create failure, natural exit, explicit close, owner destroy, plugin unload, and model-facing persistent timeout/cancellation leave no owner shell, process, timer, buffer, or registry residue. The next persistent `bash` call must be a clean shell; one-shot cancellation cleanup is tested separately. |
| Workspace | Writes inside the policy root succeed; writes outside it fail. A model-supplied external cwd cannot widen the bind. |
| Persistent shell | cwd, environment, function, and background-job state persist for the owner only during a live shell; clean shell flags are used. Model-facing timeout/cancellation resets the owner shell, so the next call starts clean. Lower-level SIGINT/abnormal backend behavior is tested separately. |
| Compatibility | `pwsh` remains registered and usable; the plugin does not replace or mutate it. |
| Additional modes | Both `bash-wsl` and `bash-git-bash` appear in the actual Web/Desktop roster and mount successfully. Each retains that host version's shipped Standard plugins except stock one-shot Bash, replaced by persistent Bash; preserve `pwsh`, all other capabilities, stock IDs and selected default. Keep `!!js` expressions unevaluated until the correct scoped activation. |
| Mode prompt | Each mode assembles exactly one matching plugin usage section, without the other mode's default-shell instructions. Check WSL `/mnt/c/...` versus Git Bash `/c/...` and explicit full-access guidance; no personal data or interpolation. |
| Persistent native Git Bash | Use the real Windows `bash.exe` through the actual host's official PTY runtime, not PowerShell/WSL. Standing full-access is required; restricted and stale-policy calls perform zero discovery/spawn. State, ownership, serial calls, limits, timeout/cancel/reset and native process-tree cleanup are mandatory in both supported hosts. A one-shot approval never grants a persistent shell. |
| Native PTY control | Keep control separate from terminal output. Reject malformed/oversized frames, invalid readiness, unexpected acknowledgements and invalid exit facts. Stdin writes await callbacks and backpressure; asynchronous EPIPE, close and late error become one ordered transport failure, with permanent adapter listeners removed at cleanup. Preserve a valid exit packet arriving after ordinary child completion; absent exit/EOF settles within the disposal grace and removes timers/listeners. |
| Native prompt and protocol | Continuous background output must not revoke a complete controlled prompt or cause a successful command to time out. Git emits `OSC 133;D;<status>;__DSH_PERSISTENT_BASH_PROMPT__ BEL` and the later visible `__DSH_PERSISTENT_BASH_PROMPT__` in one builtin write. ConPTY may forward the control event before repainting earlier body/CSI output, so native readiness requires the exact complete payload and later visible sentinel, not byte adjacency. Reject noncanonical or out-of-range `0..255` status, extra fields, wrong markers, missing BEL, marker-only/text-only and cross-operation stale pairs; the rolling text carry remains bounded. The marker is not authentication or the broker control channel. WSL retains its literal-space, byte-adjacent producer/wire contract. Incomplete/wrong prompts and promptless silence still fail readiness. Use the actual host emulator to prove DSR/DA replies, require reply delivery before readiness/new sends, and exercise bounded protocol-input/reply failure and exactly-once disposal. A noisy natural-exit test must first prove successful preparation on the same shell and track PID plus creation time before that shell exits; a reused PID is not residue. |
| Native cleanup observation | Natural exit with live delayed or continuously noisy background work must leave no helper, ConHost, Bash or background process while the DSH Host is still alive. Observe the complete delayed-marker window and compare creation identities. A failed process query is a failure, never proof of zero processes. |
| Preset retirement | Removing the plugin's definitions prevents new selections. Official live-agent revision retention is not scope disposal: release all owned agents/leases, then verify no retained plugin composition, tool, prompt, terminal or process remains. Unrelated stock compositions must survive. |
| Doctor/release | Doctor is read-only/no-install. Standalone package discovery is distinct from actual-host anchor discovery. Verify clean-Bash `script`, trusted `SHELL`, `WSL_UTF8=1`, a non-ASCII distribution name, the selected distribution's authoritative direct launch, defaults/environment overrides, invalid anchors and dependencies. Release checks audit the tarball and isolated installs without mutating real profiles. |
| CLI runtime | Invoke the actual Windows CLI and its official tool/registry services with the mounted plugin in an isolated `DSH_HOME`, not a hand-written test mirror of the tool protocol. |
| Desktop runtime | Invoke the actual installed Electron/ASAR runtime with a separate isolated Desktop profile; source snapshots and CLI help are not Desktop activation evidence. Record GUI observations separately from programmatic checks. The probe source/installed `index.mjs` SHA-256 values must match the current source fixture, and real agents must resolve/mount the rc.2 `standard` preset with initialized permission metadata. D-14's independent required item is old-version runtime rejection: run the preserved 0.1.0 TGZ through actual rc.2 `loadProfileDirectory` without dependency installation, then the same owned profile through `runProfile`/Host initialization; require rc.6 peer rejection, old-layer omission, strict child/identity/cleanup evidence, and absent old tools/prompt. Ordinary old-version pnpm cache diagnostics remain SKIP and are not evidence for compatibility; missing/malformed TGZ typed rejection and cleanup remain hard checks. |

## Test seam expectations

Native protocol batching must retain high/low-water backpressure and the 1 MiB bound including in-flight input. Verify that a captured-prefix drain completes despite later background input, but never accepts an unparsed current prompt or an undelivered reply. Keep timeout, cancellation, close and late-callback cleanup assertions under both bounded and continuously active input.

Earlier tools-only acceptance and the old package hash are historical evidence, not proof of the two new modes. Bind new reports to the changed core, test fixtures, actual host and newly packed artifact. The failed restricted native-Git capability probe remains a failure for that proposed capability, not a pass or evidence for the accepted full-access alternative.

Tests should inject process discovery/spawn, WSL conversion, approval, policy, timers and identity. Assert both process calls and registry/owner state; PID/name polling alone is insufficient. New tests go under `dev/测试`, temporary directories under `测试/运行产物`, and owned fixtures are cleaned in `finally`. Security assertions must not be weakened to pass.

The unit suite must run on Linux/WSL without pretending to test Windows-only token or executable behavior. Integration cases can be gated by actual capability probes. The test output should include the skip reason and should fail if a supposedly restricted operation calls the injected spawn seam.

## Human-assisted Desktop acceptance

GUI acceptance is separate from the actual Desktop Host's background tests. For each new mode, create a fresh owned session, verify its preset and permissions through the installed Host, and run exactly two serial persistent `bash` calls. Independently inspect the selected mode and both expanded tool results; a model's final description is not tool-card evidence. Bind screenshots and call/result identities to the same current candidate, host and driver sources.

The owned-session driver first explicitly applies and reads back `workspace-write`. Native Git testing additionally requires an explicit human test grant (`DSH_GUI_ALLOW_GIT_FULL_ACCESS=1`) before launch; it then applies and reads back `danger-full-access` for that session only. Permission-command acknowledgement and the pre-prompt projection must match. Mode selection, a remembered profile default, or one-shot approval cannot provide this grant. Do not change global permission settings or user profiles.

In Desktop rc.2, clicking the window's X hides it to the tray. Normal-exit acceptance requires the tray's **Quit DeepSeek Harness** action (or the application's Exit action), followed by successful PID/creation-time and owned WSL-ledger checks. A forced cleanup after the bounded observation window is a failed normal-exit check, not a pass.

The human observation window is ten minutes, separate from the unchanged two-minute real-turn timeout and the RPC, cancellation and cleanup deadlines. It ends early when the Desktop child closes. Expiry without a normal exit still fails; a longer observation window must not turn forced cleanup into successful GUI acceptance.

The reviewed driver `3afd079a242a0de07e53f9c98672a2119e4d402f8689006dac13fd93c90674ce` has one identified Git normal-close observation-ordering defect: it samples `lineageBeforeTerminate` after normal close, then treats that empty query as its prepositive observation. Never edit or relabel the raw FAIL. Only this exact driver and the sole error `owned Windows CIM prepositive lineage unavailable` may use the test-only `git-normal-close-gap-evidence.mjs` supplement. It reopens and hashes five contained regular files: raw result, official READY, wrapper launch, independent prepositive CIM and independent postempty CIM. The full session, candidate, host, source, permission, call/result and process-creation identities must agree; the samples must straddle normal close. All original permission, protected-fixture and cleanup assertions remain mandatory. Timeout, cancellation, forced termination, query failure, residue, another error or missing evidence still blocks qualification.

The supplement reports `QUALIFIED_KNOWN_GAP` separately from the immutable `rawDriverStatus=FAIL`. Both GUI gates recompute it from those files rather than trusting an acceptance flag; the aggregate Git mode must match the recomputed mode. Offline positive/negative regressions validate this narrow evidence path, not the live tool execution itself.

An already authenticated, protected test fixture may be reused without creating a new transient profile. Record this scope explicitly: no transient root was created or removed, the fixture and canonical archive were preserved, realpath containment holds, and both mode drivers have clean process/ledger evidence. Do not delete the authentication fixture or set `temporaryRootRemoved=true` merely to satisfy a temporary-profile check. The canonical archive's preservation hash must not replace the new candidate's identity.

## Suggested commands

When working from WSL, invoke a verified Windows `node.exe` or the existing owned Windows launcher. Do not invoke the Desktop `resources/runtime/bin/node` shell shim across WSL interoperability: its Unix-side `ELECTRON_RUN_AS_NODE` export did not select Windows Node mode in a recorded audit and instead opened the ordinary Desktop. A failed source-inspection attempt must not fall back to launching a real profile.

Run these commands from a source checkout; the npm tarball does not contain the source-only `scripts/`, `docs/`, `dev/`, or `src/` directories.

```sh
npm run typecheck
npm test
node scripts/release-check.mjs
```

The exact npm scripts are owned by the package manifest. If a repository does not define one of these commands, the release check must report the missing command as a failure rather than silently omitting the gate.
