## 隔离 GUI 启动证据（非完整 UI 验收）

2026-10-09 在确认没有现有 DeepSeek Harness 进程后，使用实际安装的 `DeepSeek Harness.exe` 启动了一份测试实例。实例同时使用了测试目录内独立的 `DSH_HOME`、`--user-data-dir`、workspace 和 update-journal，并设置 `DSH_TELEMETRY_DISABLED=1`；未接触真实 `web`/`desktop` profile、账号、cookie、API Key 或模型业务。主进程及其 Desktop host 子进程命令行均指向本次测试目录，清理记录显示随后按主 PID 回收了整棵测试进程树，真实 Harness 无残留。

Computer Use 重新读取到实际窗口的辅助树，页面为 Desktop 欢迎页，仅有“登录”和“添加 API Key”，因此没有点击或输入任何认证信息。窗口截图通道重试两次超时；更重要的是当前隔离实例没有本地登录/模型会话，无法展示插件工具调用或提示词组装。故 D-16 只能记录为 `SKIP`（真实 GUI 启动/窗口可见已观察，但插件视觉、工具卡片和模型会话行为未验收），不能以 headless Electron context probe 替代视觉验收。对应测试目录曾生成的运行目录已在记录后删除，避免保留宿主生成的 credential/session 文件。

## 可复现命令

在 Windows Node 宿主上，从仓库根目录运行：

```text
node 测试/桌面/desktop-context-probe.mjs --tgz <Windows 绝对路径的 dsh-plugin-bash-wsl-0.2.0.tgz>
```

脚本使用实际 Desktop Electron 的 Node mode 启动真实 `dsh-desktop-host` 所用的 `runProfile`/`loadProfileDirectory` 组合，并在真实 Cordis context 中检查工具、系统提示词和本地工具调用。它不调用 CLI 来代替 Desktop。默认临时目录在 `测试/运行产物`，结束时精确清理；仅使用 `--keep` 时保留故障现场。

安装包与发布门禁由同一测试线程的 `scripts/release-check.mjs` 负责。门禁必须使用离线安装、不能传 `legacy-peer-deps`，且所有临时目录仍在 `测试/运行产物`。
